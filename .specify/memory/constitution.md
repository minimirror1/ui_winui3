# Animatronics Control Center Constitution

## Core Principles

### I. 작업 규칙은 AGENTS.md 가 정본이다

이 프로젝트에서 어떻게 일할지는 저장소 루트의 `AGENTS.md` 에 적혀 있다.
생각하고 코딩하기, 단순함 우선, 수술적 변경, 목표 기반 실행, git 가지 전략 —
다섯 항목 모두 거기 있다.

여기에 같은 내용을 옮겨 적지 않는다. 규칙이 두 군데로 갈라지면 어느 쪽이
진짜인지 모호해지고, 한쪽만 고쳐졌을 때 알아챌 방법이 없어진다.
`AGENTS.md` 와 이 문서가 어긋나 보이면 `AGENTS.md` 가 이긴다.

### II. 구현 전에 실패하는 테스트가 있어야 한다

`AGENTS.md` 4항(목표 기반 실행)을 이 프로젝트에서 구체화한 형태다.
새 동작은 먼저 테스트로 적고, 그 테스트가 **올바른 이유로** 실패하는 것을
확인한 뒤에 구현한다.

테스트가 바로 통과해 버렸다면 실패를 본 적이 없다는 뜻이므로, 구현을
일부러 망가뜨려 그 테스트가 실제로 잡아내는지 확인한다.

### III. 성능 약속은 숫자로 고정한다

"느려지지 않는다" 같은 약속은 말로 두지 않고 통과 기준이 있는 테스트로
바꾼다. 가능하면 시간 측정보다 결정론적 기준을 주 기준으로 삼는다 —
예: 느린 출력을 주입해도 생산자 쪽 시간이 변하지 않는가.

## 범위 밖

이 문서는 절차를 정하지 않는다. spec-kit 의 단계(`/speckit-specify` →
`/speckit-plan` → `/speckit-tasks` → `/speckit-implement`)를 쓸지 말지는
작업마다 정한다. 지금까지 `docs/plans/` 에 날짜별 계획 문서를 쓰던 방식도
그대로 유효하다.

## Governance

- `AGENTS.md` 가 작업 규칙의 정본이고, 이 문서는 그것을 가리킨다.
- 이 문서를 고칠 때는 `AGENTS.md` 와 어긋나지 않는지 먼저 확인한다.
- spec-kit 이 이 프로젝트에 맞지 않는다고 판단되면 `.specify/` 와
  `.claude/skills/speckit-*` 를 지우면 된다. 다른 것은 건드리지 않는다.
